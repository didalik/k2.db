# k2.db

A compact, standalone public submodule for Dream Big's requestor flow: it lets a mobile or local client generate an SSH identity, connect to a matching Agent, optionally obtain a Stellar testnet grant, and expose a local service through a reverse SSH tunnel.

This repository is intentionally self-contained so it can be cloned alone without the full K2 monorepo. The requestor app and its local status page live here, along with the minimal browser-side helpers and utilities it needs.

## What this repo contains

- `requestor/` — the actual requestor client runtime
  - `run.js` — orchestrates key generation, matching, grant handling, and SSH tunnel setup
  - `server.js` — serves the HTTPS status page and static assets locally
  - `tm.js` and `stellar.mjs` — Stellar testnet grant plumbing
  - `Makefile` — one-command startup for the requestor
- `requestor.html` / `requestor.mjs` — browser UI used by the local HTTPS status page
- `intro.mjs` / `intro-hbs.html` — simple introductory/demo browser page
- `lib/util.mjs` — minimal browser utility used by the intro/status UI
- `style.css` / `favicon.ico` — static assets for the UI

## Why this exists

The app is designed to run in an environment like Termux on Android:

- the device has no public IP of its own
- it needs to establish a tunnel to a remote agent
- it must present a local status page while waiting for a match/grant
- it may use a Stellar testnet grant gate before proceeding

The requestor therefore does three main things:

1. Creates an ephemeral SSH keypair for the session.
2. Connects to the Dream Big websocket-based matching flow.
3. Uses a reverse SSH tunnel to forward a local service through the remote Agent.

## Quick start

From the repository root:

```bash
cd requestor
npm install
make requestor
```

This starts the requestor and brings up the local HTTPS status page.

Default behavior:

- local demo service: `localhost:8099`
- status page: `https://localhost:8443/`
- websocket target: `wss://qa.ws.kloudoftrust.org/db`

## Configuration

The requestor reads several environment variables:

- `DB_WS_URL` — optional websocket URL; defaults to the QA deployment
- `DB_LOCAL_PORT` — port of the local service to forward; default `8099`
- `DB_REMOTE_PORT` — port requested on the Agent side; defaults to `DB_LOCAL_PORT`
- `DB_STATUS_PORT` — local HTTPS status page port; default `8443`
- `DB_REQUESTOR_NAME` — optional friendly requestor name; default `termux`
- `DB_TM_ISSUER_PK` — optional Stellar public key for the TM grant gate

If `DB_TM_ISSUER_PK` is unset, the TM grant step is skipped. That is useful for local development or test-only scenarios.

## Example run

```bash
cd requestor
export DB_LOCAL_PORT=8099
export DB_REMOTE_PORT=8099
export DB_STATUS_PORT=8443
export DB_TM_ISSUER_PK='your_stellar_public_key_here'
make requestor
```

Then open:

```text
https://localhost:8443/
```

## Local certificate note

The local status page uses a self-signed CA certificate generated by the requestor itself. Because browsers do not trust a localhost certificate from a local CA automatically, you may need to install the generated CA certificate once on the device before the browser accepts the page.

The relevant files are generated under:

```text
requestor/.certs/
```

## Project status

This repo is a small operational utility for the Dream Big requestor flow rather than a general-purpose database library. It is built around a browser-facing status UI, a local SSH reverse-tunnel flow, and optional Stellar testnet integration.

## Notes

- This repository is intentionally designed to be usable on its own.
- It includes copies of supporting utility code so it does not depend on a larger monorepo checkout.
- The app is focused on local tunneling and remote matching workflows rather than application data storage.

If you are using this repo as part of the Dream Big ecosystem, the requestor is the component that exposes a local service to a remote Agent over a secure SSH reverse tunnel.
